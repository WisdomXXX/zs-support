# M1 实机验收记录 — 2026-10-21

版本：zs-support 0.2.0。设备：ZSM1 智航版，本体 RK3588 0.3.3，NX Hermes_M_v0.3.1。客户端：当前 Ubuntu 工作站。全部测试在用户已连接的机器人上执行；没有重启服务、修改网络、改机器人配置或发布运动控制指令。

## 修复与根因

1. 本地保存的旧连接指向 ZSL1/firefly，连接 M1 时凭据与路径不匹配。connect 改为直接使用上次/默认产品连接配置，失败时提示并尝试替代配置；显示产品来源，支持 --product 明确指定。
2. helper 的 umask 077 被 sudo 继承，脚本成功后归档为 root/0600，SSH 账号无法下载。仅对本次新生成的普通归档 sudo chown 给当前 SSH 账号，保留私有权限；历史归档与目录权限不变。
3. `/home/robot/robot_launch_log` 是固件维护的软链接；旧代码直接拒绝，导致脚本失败后目录回退也失败。现在解析显式根路径并展示目标，目录内部链接仍跳过。
4. 仅 source `/opt/ros/humble/setup.bash` 未加载实际机器人环境。现同时加载 `/opt/runtime/env.bash` 和实际存在的 overlays，继承 domain 24、rmw_zenoh_cpp、板卡消息库等配置。
5. 导航场景的 `/nav_lite/start_cmd` 在 ROS 图可见，但当前 NX 库缺少 `NavLiteTrackCmd` 类型符号，导致 recorder 启动异常。现在动态检查消息库和符号，列出不可用话题并从场景录制中排除；手工 --topic 指定不可用类型则明确报错。
6. 启动检查不能把创建的空 SQLite 当作录制中；实时查询 SQLite 又可能干扰 rosbag2 的写锁。最终实现读取 recorder 自身就绪日志，进程结束后才检查数据库消息和 metadata，避免争锁。
