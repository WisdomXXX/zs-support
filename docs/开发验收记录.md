## 自动化验证

执行 `PYTHONPATH=src python3 -m unittest discover -s tests -v`，最终 **29 项测试全部通过**。
覆盖内容：

- M1 真实 0.3.3 / Hermes_M_v0.3.1 样例，小狗 622 条目及 rootfs 排除；标准 nx 规则使用合成样例，未伪称真实固件样例。
- 配置覆盖、别名、产品/板卡账号隔离、空/错误 YAML、重复字段、未知版本、NX 失联、人工配置证据。
- JSON 错误、缺参不阻塞、Tab 补全只读本地数据、主机地址转义与密钥/认证错误映射。
- 真实本地子进程模拟 ROS：启动、持久化重启、重复启动拒绝、停止、精确拉取及缓存复核。
- PID 启动时间变化、设备重启标识、错误板卡身份均不发送停止；独立的其他录包进程保持运行。
- 空间不足、缺少 ROS setup、未知存储格式、Topic 尚不可见、路径失配与成功后保存覆盖。
- Bag 按内容扫描、深度限制、地图新旧根优先级/history_map、多字节及 shell 特殊字符路径。
- 真实本地 rsync 文件传输；失败后保留中间文件并复用、重试、取消、静态源变化拒绝、链接跳过。
- M1 本次新归档与旧归档区分、gzip/tar 校验、空/坏归档、无新产物、脚本失败、超时、0.3.2 边界、目录回退及取消不回退；sudo 内部文件锁验证脚本不重叠执行。

`scripts/verify_package.py` 另外检查：deb 包名/版本、任意目录运行、资源可用、唯一入口、有/无/故障 zt 时的安装升级卸载脚本、Bash 新 Shell 动态加载和产品/场景参数补全、Zsh 自动注册与手动加载。

构建 wheel 时开发机全局 ROS 的 PYTHONPATH 导致旧版 setuptools/packaging 混入构建过程；在独立 venv 且清除该次命令的 PYTHONPATH 后构建成功。没有修改系统 ROS 或系统 Python 包。
