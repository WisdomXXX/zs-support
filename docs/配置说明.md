# 配置说明

优先级：命令参数 > `ZS_SUPPORT_*` 环境变量 > 用户 `~/.config/zs-support/config.json` > 系统 `/etc/zs-support/config.json` > 内置资源。
JSON 对象递归合并，数组整体替换。无须为正常操作创建配置文件，也无须配置账号密码。

用户配置示例：

```json
{
  "product": "zsm1",
  "board": "body",
  "min_free_bytes": 1073741824,
  "connect_timeout": 5,
  "command_timeout": 30,
  "transfer_timeout": 3600,
  "script_timeout": 180,
  "stop_timeout": 40,
  "retries": 2,
  "scan_depth": 3,
  "products": {
    "zsm1": {
      "boards": {
        "body": {
          "log_scripts": ["/opt/runtime/bin/get_robot_log.sh"],
          "ros_setups": [],
          "ros_overlays": ["/opt/robot/robot_nav/install/setup.bash"],
          "paths": {
            "log": ["/tmp/log/alg_data", "/home/robot/robot_launch_log"],
            "map": ["/userdata/alg_data/map", "/ota/alg_data/map"]
          }
        }
      }
    }
  }
}
```

可用环境变量：`ZS_SUPPORT_PRODUCT`、`ZS_SUPPORT_BOARD`、`ZS_SUPPORT_HOST`、`ZS_SUPPORT_OUTPUT`、`ZS_SUPPORT_ROS_SETUP`、`ZS_SUPPORT_LOG_SCRIPT`、`ZS_SUPPORT_INTERFACE`，以及上述所有数值项的大写形式，例如 `ZS_SUPPORT_MIN_FREE_BYTES`、`ZS_SUPPORT_RETRIES`。HOST 在 connect 时应用到 BOARD（默认 body），后续对所选板卡的显式入口仍核验身份。

支持直接覆盖的命令参数包括 `--product`、`--board`、`--output`、`--ros-setup`、`--log-script`、`--min-free-bytes`，连接时用 `--body-host`/`--compute-host`/`--interface`。数值类型或产品结构有误返回配置错误。产品别名归一化；不静默回退到其他产品。

数据路径优先级：`--remote-path` > 该板卡 `--save-path` 保存的已验证路径 > 上述产品配置候选路径。
覆盖按稳定板卡 ID 隔离，存储于状态目录 `path_overrides.json`。原始数据下载成功后才保存覆盖。

M1/L2 本体入口为 `192.168.168.168`、`192.168.234.1`，优先尝试本机网卡直接覆盖的地址；显式地址只使用该地址。运行中失联时可回退默认入口，但必须是同一板卡身份。L2 高速入口 `192.168.144.100` 通过 connect 的 `--fast` 显式选择。

ROS 默认探测 `/opt/ros/*/setup.bash`，多个版本并存要求指定；叠加配置中实际存在的 overlays，不固定 Humble。启动时读取 record 帮助、Topic 列表和可用 storage 插件。老固件无法枚举插件时仍可使用设备默认格式；显式请求无法证实的格式则拒绝。

`map_required_files` 可在板卡下配置必需的相对文件名列表，缺失或空文件会报告 `incomplete_map`。默认不猜测各固件地图格式，需实机确认后配置。列表相对本次采集路径，整根目录采集时应按根目录格式设置。

会话 JSON 记录产品、板卡身份、UTC 开始时间、远程绝对路径、Topic、格式与远端进程证据。JSON 时间为带时区 ISO 8601（UTC），普通终端显示转换为客户端本地时区，目录使用 UTC 命名。设备重启、进程退出或网络不可达会重新核验，缓存不作为停止依据。

客户端首次 SSH 使用 accept-new 记录主机公钥，变更时拒绝连接。运行参数中不包含密码，SSH 使用 sshpass 文件描述符输入，sudo 密码由远端请求 stdin 传入；客户无需处理密码。配置文件中内置凭据并不是额外的安全隔离机制。

日志脚本使用固定绝对路径，可在任意工作目录执行；实现从脚本目录以绝对路径调用，保留兼容。只有把 `log_scripts` 显式设为空数组，才会有限扫描 HOME 下两层作为兜底，不会扫描整台设备。

## 0.2.0 M1 实机适配

M1 日志首选 `/home/robot/robot_launch_log`（解析到本次启动目录），本体回退还含 `/userdata/log`；NX 额外采集 `/tmp/log/alg_data`。仅显式根路径解析软链接，内部链接不递归跟随。

ROS 预检和实际录制都会在 ROS 基础 setup 后加载 `/opt/runtime/env.bash`，再加载已存在的 overlays。该文件包含 M1 的 domain 24、rmw_zenoh_cpp 与各板卡运行配置。显式 `--ros-setup` 仍支持覆盖基础环境。

M1 脚本新归档可能为 root/0600；工具只对本次新生成的普通归档执行 sudo chown 给 SSH 账号，校验 inode 后读取。其他归档与目录权限不作调整。

场景预览会读取话题类型并在正确 ROS 环境内检查 rosidl_typesupport_cpp 库及消息符号。M1 的 NavLiteTrackCmd 不存在于当前库，自动报告并跳过。一次 bag 命令内短时复用 ROS 探测，启动仍重新核验保存目录空间与权限。录制就绪使用自身日志事件判断，不读取正在写入的 SQLite；退出后检查实际消息和 metadata。

## 多网卡

默认根据网卡地址和系统路由选择 SSH/rsync 的 BindInterface。`connect --interface <网卡>` 保存明确选择，`ZS_SUPPORT_INTERFACE` 或配置中的 `interface` 可覆盖。连接时优先当前直连入口，同时查询两块板卡；不会修改路由。AP234 到内网168 仍需要有效系统路由，连接失败会提供 `sudo ip route add 192.168.168.0/24 via 192.168.234.1 dev <实际机器人网卡>` 提示。网线直连应使用网线的路由，不经 AP。

## 0.3.1 命令与话题

无参数启动直接显示 -h 帮助，推荐入口为 connect、info、bag、status、stop、pull、doctor、completion。旧 rec/log/map/collect 仍支持。地图固定从 compute 获取，map 路径覆盖请放在 compute 板卡配置下；配置中的默认 board 不影响地图来源。组合采集 --board 仍可指定其他类型的数据来源。

Topic 配置随程序发布，位于 `src/zs_support/resources/topics/`。M1 导航 183 个、建图 18 个、定位 18 个；合并场景去重，可录数量仍以远端当前发布状态和类型库为准。普通拉取显示摘要，--json 与采集清单保留路径探测、校验等完整字段。
